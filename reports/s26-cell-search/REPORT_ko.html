1. 판정: S26+ 기지국 탐색 개선 MVP의 현재 한계

2026-11-09 공개 자료 조사 · 10쪽 의사결정 보고서

검토 대상은 R4에 연결한 외부 GPS의 위치를 BLE로 갤럭시 S26+에 전달해, 휴대폰의 실제 셀룰러 기지국 탐색을 개선하는 구조다. 이전 Fold3의 GNSS 첫 위치 획득 실험과 목표가 달라졌다. 이번 보고서에서 “기지국 탐색”은 지상 이동통신망의 탐색·셀 선택을 뜻하며, GPS 위성 탐색이나 지도 위치 표시를 뜻하지 않는다.

판정은 두 가지로 나뉜다. 일반 배포 앱만으로 이 구조를 제품화하는 현재 MVP는 폐기를 권고한다. 그러나 모든 직접·우회 경로가 없다고 판정할 수는 없다. Android의 시스템·통신사 권한 경로와 AOSP shell 권한 선언이 존재한다. 따라서 사용자의 “경로가 없으면 폐기” 조건이 모든 가능한 권한까지 포함한다면, 그 조건은 아직 충족되었다고 입증하지 못했다.

판단의 근거와 강도

확인된 사실그 사실이 허용하는 판단
외부 BLE 좌표 수신은 앱 데이터 처리다수신만으로 GNSS HAL이나 모뎀에 전달되었다고 볼 수 없다
위치 캐시 주입과 GNSS 보조정보 주입은 다른 경로다이름이 같은 injectLocation 호출을 가속 증거로 쓸 수 없다
네트워크 스캔 API에 특수 권한 경로가 있다“모든 우회 불가능”이라는 단정은 배제해야 한다
S26+ 실물 연결·계측이 제공되지 않았다개선율·지연·성공률은 모두 미측정이다

일반 앱 범위의 폐기 권고는 물리적으로 절대 불가능하다는 증명이 아니다. 필요한 제어 경로와 효과 검증이 확보되지 않은 상태에서 GPS 구매, 앱 UI, 클라우드 연동을 더해도 사용자의 필수 기능을 만족시킨다고 말할 수 없다는 개발 판단이다. 권한 실험을 허용하는 연구용 프로토타입은 별도 보류 대상으로 남긴다.

이번에 남긴 결과물

10쪽 보고서, 조사 근거 목록·소스 발췌·조회 해시, 별도 논리 검토서, Windows에서도 실행할 수 있는 읽기 전용 진단 도구를 작성했다. 진단 도구는 S26+ 모델·OS·shell 권한 기록을 수집하며, 주입·모뎀 변경·성능 향상을 실행하는 앱이 아니다. 기존 Fold3 APK와 소스는 보존한다. 실제 S26+ 가속 구현과 성능 검증은 미달성이다.

2. 무엇을 개선해야 성공인가

사용자가 체감하는 “통신이 다시 되는 시간”에는 여러 단계가 포함된다. RF 채널 탐색, 적합한 셀 선택, 망 등록, 데이터 연결 설정, 인터넷 검증은 서로 다르다. 어느 하나의 콜백이 빨리 왔다고 전체 과정이 빨라졌다고 결론 내리면 안 된다. 내장 GPS의 TTFF는 이 단계들과 별개의 지표다.

제안 구조에서 아직 연결되지 않은 단계

R4 GPS → BLE → Android 앱 → 위치의 신뢰성·유효기간 판단 → 위치별 후보 주파수/망 정보 → 권한 있는 모뎀 제어 → 실제 탐색·등록 개선

앞의 위치 전달 부분은 구현 가능한 일반 통신 기능이다. 하지만 GPS 좌표에는 현재 접속 가능한 통신사의 채널, 대역, 접근 제한, 셀의 혼잡 상태가 자동으로 포함되지 않는다. 좌표를 이용하려면 최신 후보 정보와 오류 시 전체 탐색으로 돌아가는 방식이 필요하다. 그리고 후보를 계산할 수 있어도 휴대폰이 그 정보를 실제 탐색에 사용하는 제어 경로가 있어야 한다.

지표측정하는 것해석의 제한
GNSS 첫 fix 시간위성 기반 위치 획득기지국 탐색 개선의 대체 지표가 아님
네트워크 스캔 결과 시간요청한 스캔의 결과 도착망 등록이나 데이터 연결 완료와 다름
서비스 복귀까지 시간단말이 서비스 상태로 돌아옴RF 탐색 외 단계·콜백 지연도 포함
셀룰러 데이터 사용 가능 시간셀룰러 경로의 실제 연결 복구Wi-Fi 경로·DNS·서버 지연을 분리해야 함

목표를 평가할 때는 통신 서비스 복귀 시간을 사용자 관점의 주지표로 삼고, 가능한 경우 모뎀 로그로 RF 탐색 시간을 별도로 분리해야 한다. 두 지표를 함께 기록할 수 없다면 “RF 탐색이 빨라졌다”보다 좁고 정확한 결과 이름을 사용한다.

ETSI TS 38.304는 저장된 주파수·셀 정보를 이용한 선택과 정보가 없는 초기 선택을 구분한다. 이는 탐색 정보가 도움을 줄 수 있다는 기술적 배경이다. 그러나 이 규정은 Android 일반 앱에 모뎀 캐시 쓰기 권한을 부여하지 않는다. 또한 표준에 저장 정보가 있다는 사실만으로 외부 GPS가 기존 모뎀보다 나은 정보를 줄 것이라고 가정할 수 없다. [S14]

50노드 BLE 시뮬레이션의 전달 성공률이나 기존의 90% 목표는 이번 휴대폰 기지국 탐색 성능을 입증하지 못한다. 이번 보고서에는 그 결과를 대체 실측값으로 싣지 않는다.

3. 최신 S26+가 더 유리한가

삼성전자서비스의 국내 출시 사양은 S26+를 SM-S947N, Exynos 2600, RAM 12GB, Android 16 / One UI 8.5로 안내한다. 같은 자료는 출시 국가에 따라 사양이 다를 수 있다고 명시한다. 글로벌 발표에도 지역별 AP 차이가 있어, S26+라는 제품명만으로 단일 모뎀·펌웨어 구성을 확정할 수 없다. [S01, S03]

별도로 확인한 삼성의 SM-S947B 업데이트 페이지는 2026-10-29 빌드 S947BXXU5BZJA에 Android 17을 표시하고, 2026-09-30 항목에 One UI 9를 안내한다. 이것은 해당 모델·배포 이력의 정보이며 국내 SM-S947N이나 사용자 단말의 설치 상태를 증명하지 않는다. 출시 OS와 조사 시점의 업데이트 OS는 다른 정보이므로 서로 모순이라고 볼 수 없다. [S02]

사양과 기능 접근권은 분리해야 한다

최신 OS최근 API와 진단 환경을 사용할 가능성특정 API의 삼성 구현·권한·동작
GNSS·모뎀 세대수신·전력·연결 기능이 달라질 가능성외부 위치 보조 시 추가 이득과 그 크기
UWB·BLE 기능단말 간 정보 전달·거리 응용에 활용 가능셀룰러 모뎀 제어 권한을 제공하는지

최신 하드웨어가 기존 기기보다 자체 성능이 좋을 가능성과, 외부 GPS를 넣었을 때 추가 이득이 생기는지는 서로 다른 가설이다. 자체 보조정보·캐시가 이미 충분하다면 외부 장치의 추가 이득은 작을 수도 있다. 반대로 특정 지역·전파 조건에서 이득이 있을 가능성도 배제할 수 없다. 둘 다 이번 조사에서는 실측 근거가 없는 추론이다.

따라서 “S26+라서 Fold3보다 우회가 쉽다”, “GPS가 더 빨라지므로 기지국도 빨라진다”는 주장을 채택하지 않는다. 사용자의 실제 모델, 빌드, SIM·통신사, 권한, 수신 조건을 먼저 확인해야 한다. 이번 진단 도구는 그중 모델·빌드와 shell 권한 기록을 수집하도록 준비했다. 통신사 권한이나 실제 HAL 연결 가능성은 이 도구만으로 확정하지 않는다.

원문 품질 주의: S01에는 표 설명 중 S24라는 편집 잔재가 있지만, 표의 제품 행과 제목은 S26이다. 필요한 모델 행을 사용했으며 이 문서 하나로 실제 단말의 내부 구현까지 추정하지 않았다.

4. 기존 클라우드 조사·구현에서 재사용할 것

이번 작업은 기존 GitHub 저장소의 커밋 eb12bf5a1df8aae8922129fb01760138c298af4e에 있는 Fold3 보고서·Android 소스·검증 기록을 참고했다. 대상 파일은 android/gnss-assist/REPORT_ko.md와 해당 디렉터리의 앱·시험 도구다. 이를 실제 Fold3 측정 데이터로 취급하지 않는다. 기존 보고서도 실물 설치와 성능 측정은 미실행이라고 구분했다. [S04]

기존 앱은 api_return과 injection_confirmed=false를 분리하고, mock·오래된 위치·미래 시각 등을 제외했다. 이 원칙은 이번에도 유효하다. 그러나 정상 콜백, APK 빌드 성공, true 반환값 중 어느 것도 삼성 GNSS 칩의 실제 주입이나 셀룰러 모뎀의 탐색 개선을 입증하지 않는다.

기존 문서의 “Shizuku가 범용 우회로는 아니다”라는 표현은 유지할 수 있다. 다만 이를 “shell에는 관련 권한이 전혀 없다”로 확대하면 틀린다. 이번에는 AOSP Shell manifest의 LOCATION_HARDWARE, MODIFY_PHONE_STATE, NETWORK_SCAN 선언을 확인했다. 이 반례 때문에 우회 경로를 모두 배제하는 결론은 채택하지 않았다. [S11]

재사용과 보존 판단

GNSS 이벤트 기록·시간 측정·입력 검증 코드는 향후 GNSS 실험의 출발점으로 보존한다. 이번에는 앱 제목만 S26+로 바꾸거나 TTFF를 기지국 탐색 지연으로 바꾸어 성능 앱을 만들어 내지 않았다. SDK 35로 만든 기존 APK가 새로운 OS에 설치될 가능성이 있더라도, 설치·런타임 권한·삼성 펌웨어 동작은 따로 검증해야 한다.

R4에서 스마트폰으로 보내는 버전 1과 스마트폰끼리 정보를 보내는 버전 2도 동일한 한계를 가진다. 송신 단말을 바꾸어도 수신 스마트폰의 GNSS·모뎀 권한이 자동으로 생기지 않는다. Supabase나 웹 서비스는 로그·계정·정보 배포에 쓸 수 있지만 이 권한 경계를 해결하지 못한다. 현재 단계에서 클라우드 연동을 늘리는 것은 핵심 기능 입증을 대체하지 못한다.

5. GNSS 직접 주입과 우회 경로의 실제 의미

이름보다 호출의 도착점을 확인해야 한다

조사한 AOSP LocationManagerService.injectLocation()은 LOCATION_HARDWARE와 ACCESS_FINE_LOCATION을 검사한 뒤 공급자 관리자의 injectLastLocation()을 호출한다. 이 위치는 마지막 위치 캐시다. 이 메서드 자체가 GNSS HAL의 aiding 입력을 직접 호출하는 구현은 아니었다. 캐시 변화가 다른 동작을 통해 간접 영향을 줄 가능성까지 배제한 것은 아니지만, 그러한 효과는 별도 호출 경로와 계측으로 증명해야 한다. [S05]

한편 GNSS 공급자에는 GnssNative.injectLocation()을 부르는 내부 경로가 있고, 그 지점은 mock 위치를 거부한다. GNSS HAL의 IGnss에는 injectLocation, injectBestLocation, 시간 주입 인터페이스가 존재한다. 따라서 직접 주입이라는 개념 자체가 없는 것은 아니다. 문제는 일반 BLE 앱이 해당 입력을 합법적인 실행 권한과 제조사 구현을 통해 전달할 수 있느냐이다. [S06, S07]

숨겨진 injectLocation권한 검사·캐시 갱신 구현 확인GNSS HAL 주입과의 직접 연결

OEM GNSS HAL 연동HAL에 주입 인터페이스 존재삼성 접근권·계약·단말 동작

외부 GPS 좌표 한 점은 위성 궤도 데이터, 신뢰할 수 있는 시간, 정확도·시각·유효기간을 갖춘 보조정보 전체와 동일하지 않다. 좌표를 받아들여도 그 값이 오래됐거나 실제 위치와 다르면 탐색에 도움이 되지 않을 수 있다. 공급자의 품질 판단과 불확실성 처리 없이 좌표를 믿게 만드는 구현을 제품 기능으로 채택하지 않는다.

또한 GNSS aiding 경로를 확보했다고 하더라도 이번 최종 목표에는 한 단계가 더 필요하다. GNSS 획득의 개선이 지상 셀룰러 탐색·등록의 개선으로 이어지는 호출 또는 프로토콜 관계를 확인해야 한다. 이번 자료에서는 외부 BLE 좌표에서 그 결과까지 연결되는 완결된 S26+ 경로가 확인되지 않았다. 이는 조사 범위 내 미확인이며 모든 비공개 제조사 경로가 없다는 증명은 아니다.

6. 셀룰러 제어 API와 남아 있는 후보

requestCellInfoUpdate()는 셀 정보 업데이트를 요청하는 API다. 정확한 위치 권한을 요구하며, 업데이트는 제한되거나 보장되지 않을 수 있다. 결과를 조회하는 행위와 셀 선택·망 등록 정책을 바꾸는 행위를 동일시해서는 안 된다. 결과 콜백을 자주 요청해 화면을 빨리 갱신해도 실제 탐색이 빨라졌다고 볼 수 없다. [S08]

requestNetworkScan()은 별도의 네트워크 스캔 경로다. AOSP 전화 서비스는 MODIFY_PHONE_STATE 또는 통신사 권한을 검사하며, 위치 접근 조건도 별도로 처리한다. NetworkScanRequest는 무선 방식·대역·채널·망 식별자 등의 조건을 전달한다. 확인한 요청 형식에 외부 GPS 위도·경도를 직접 넣는 매개변수는 없다. [S08–S10]

가장 관련성이 높은 조건부 가설

신뢰할 수 있는 외부 위치 → 최신 지역별 주파수 후보 → 권한 있는 제한 스캔 → 후보 결과 활용 → 실제 서비스 복귀 개선

이 가설은 검토할 가치가 있지만 지금 구현 성공으로 표시할 수 없다. 지역·통신사별 후보 데이터가 필요하고, 지원 대역·채널 제한과 권한 검사를 통과해야 한다. 스캔 결과가 빨라져도 기존 자동 선택·등록 과정에 어떻게 반영할지 별도의 경로가 필요하다. 자동 모뎀 탐색과 경쟁하면 지연·전력이 늘 가능성도 시험해야 한다.

위치 설정이 꺼진 경우에도 제한된 스캔 예외가 있으나, 이를 “위치 권한 없이 원하는 대역을 좁힐 수 있다”로 읽으면 안 된다. AOSP 문서는 NETWORK_SCAN 권한, 대역·채널 미지정, SIM 관련 망 식별자 등 제한을 설명한다. 우회 가능성 평가는 API 이름 한 개가 아니라 실제 매개변수와 서버 검사까지 포함해야 한다. [S08, S09]

7. 우회 경로를 모두 불가능하다고 할 수 없는 이유

ADB·Shizuku

AOSP Shell manifest에는 LOCATION_HARDWARE, MODIFY_PHONE_STATE, NETWORK_SCAN 권한이 선언되어 있다. 이는 shell에 관련 권한이 전혀 없다는 주장의 반례다. Shizuku는 ADB 또는 root 등의 방식으로 구동되며, ADB 방식의 접근은 해당 실행 환경의 권한과 제조사 제한에 영향을 받는다. [S11, S13]

선언만으로 S26+에서 모든 Binder 호출이 통과한다고 보장하지 않는다. 실제 부여 상태, 호출 UID·패키지, 위치 접근, 서비스 검사, 삼성 HAL 구현을 순서대로 확인해야 한다. 권한이 관측돼도 injectLocation()의 캐시 갱신을 GNSS 주입으로 바꾸지는 않는다. 이번 읽기 전용 도구는 이 중 초기 조건을 확인할 자료를 모은다. Shizuku 서버나 네트워크 스캔 실행 코드는 아직 적용하지 않았다.

통신사·OEM 협력

Android UICC carrier privileges는 SIM에 있는 인증서 규칙과 앱 서명을 연결해 일부 API 권한을 제공한다. 통신사 협력이 있다면 플랫폼 서명 없이 배포되는 앱에도 특별 권한이 생길 수 있다. 따라서 “삼성 시스템 앱만 유일한 방법”이라는 결론 역시 지나치다. 다만 사용자의 현재 앱에 이러한 권한이 있다는 증거는 없다. [S12]

OEM 협력은 GNSS HAL, 전화 서비스 또는 제조사 모뎀 인터페이스와 연결하는 별도의 통합 경로다. 이 경우에도 좌표 입력의 안전성, 모뎀 사용 방식, 서비스 복귀 효과를 실기기에서 확인해야 한다. 공개 HAL에 함수가 존재한다는 사실은 제조사의 접근 허용이나 상용 제품 보장을 뜻하지 않는다.

root·커스텀 펌웨어 및 위성 통신

root·프레임워크 수정은 실험 범위를 넓힐 수 있지만, 이번에는 S26+ 모델별 해제 가능성이나 실제 주입 가능성을 확인하지 않았다. 따라서 root로 반드시 된다고도, 절대 안 된다고도 결론 내리지 않는다. 실물의 부트로더·펌웨어 변경은 수행하지 않았다.

위성 통신(NTN)에서 위치·시간이 무선 동작에 관계할 수 있다는 사실을 지상 셀룰러 탐색의 반증이나 입증으로 바로 옮길 수 없다. 이번 요구는 지상 기지국 탐색이고, 확인한 GNSS HAL과 지상 네트워크 스캔 인터페이스도 역할이 다르다. “GNSS는 어떠한 통신에도 영향을 줄 수 없다”라는 포괄적 주장은 하지 않는다.

남은 가능성을 숨기지 않는 것이 폐기 판단의 조건이다. 현재 일반 앱 제품 경로의 중단 권고와 특수 권한 프로토타입의 보류는 서로 다른 결정이다.

8. 실제 적용한 진단 도구와 재개 절차

이번 추가 구현은 tools/probe.py다. Python 표준 라이브러리와 Android Platform Tools의 ADB로 동작하며 Windows에서는 adb.exe를 지정한다. 대상 기기를 명시적으로 선택하고 모델·OS·보안 패치·빌드·One UI 속성, shell 패키지 권한 기록, 전화·위치 명령 도움말을 JSON에 저장한다. 속성이 비거나 명령이 실패한 경우를 성공으로 바꾸지 않는다.

Windows에서의 실행

저장소 루트에서, USB 디버깅 연결을 사용자가 허용한 S26+를 대상으로 실행한다. 기기 번호는 adb devices에서 확인한다. 외부 GPS를 구매하거나 R4를 연결할 필요는 없다.

후속 시험은 같은 S26+·SIM·장소·시간대 조건에서 기본 모드와 보조 모드를 교차 배치한다. “후보 데이터만 사용”, “외부 GPS까지 사용”을 나누면 이득이 GPS 자체 때문인지도 구별할 수 있다. 반복 횟수·실용적 개선 기준은 예비 분산과 사용자 요구를 토대로 본 평가 전에 정한다. 이번에는 성공 기준을 달성했다고 사후 설정하지 않는다.
