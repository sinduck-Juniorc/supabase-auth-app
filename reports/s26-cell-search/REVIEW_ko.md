# 보고서 논리 검토 및 사용자에게 남기는 판단 한계

검토 대상은 `verification/review-inputs.json`에 SHA-256으로 동결한 10쪽 보고서와 그 원고다. 동일 작성 에이전트의 2차 자기 검토이며 외부 전문가의 독립 심사로 표현하지 않는다. 조사 종료 이후 새로운 웹 검색·문헌 확보·제조사 문의는 수행하지 않았다. 아래 판단은 이미 저장된 자료와 코드만 사용한다.

## 1. 가장 중요한 논리적 공백: 완전 폐기의 조건은 미충족

사용자의 조건은 “직접 또는 우회 경로가 없다면 폐기”다. 조사 결과는 “일반 앱에서 외부 GPS부터 S26+의 실제 기지국 탐색 개선까지 이어지는 경로를 확인하지 못함”이다. 이 둘은 동일하지 않다. 게다가 AOSP shell 권한 선언과 통신사 권한의 네트워크 스캔은 검토할 수 있는 반례 후보다.

따라서 **모든 경로가 없으므로 반드시 폐기해야 한다는 결론은 현재 근거로 정당화되지 않는다.** 보고서 1·7·9·10쪽은 이를 명시하고 일반 앱 제품 범위의 폐기를 개발 판단으로 권고한다. 해당 범위 제한을 빼고 제목이나 마지막 문장만 전달하면 잘못된 논리가 된다.

이 문제는 본문에서 숨겨진 모순을 발견했다기보다, 사용자가 요청한 강한 폐기 판정을 충족하지 못한 중요한 미해결 조건이다. 현재 정확한 상태는 **일반 앱 MVP 중단 권고 / 특수 권한 프로토타입 보류 / 완전 불가능 판정 미확정**이다. 이 차이를 해결하기 위한 추가 조사는 요청에 따라 하지 않았다.

## 2. 근거의 적용 범위 점검

| 검토 항목 | 확인한 결과 | 남아 있는 한계 |
|---|---|---|
| GNSS 가속과 기지국 탐색 | 본문 2·5·6쪽에서 분리 | 둘 사이 인과관계는 아직 입증되지 않음 |
| injectLocation의 도착점 | 저장된 서비스 소스는 캐시 갱신 | 간접 효과나 삼성 변형까지 부정하지 못함 |
| shell 권한 | manifest 선언이 존재 | S26+ 실제 부여·Binder·HAL 사용은 미확인 |
| 통신사 권한 | UICC 기반 특별 권한 경로 존재 | 현재 앱·SIM에 부여됐다는 증거 없음 |
| 출시 OS와 업데이트 OS | 국내 N 모델 출시, B 모델 이력을 구분 | 사용자 모델·설치 버전은 알 수 없음 |
| 최신 칩셋의 장점 | 사양과 접근권을 구분 | Fold3 대비 개선율·외부 GPS 추가 이득은 미측정 |
| 스캔 결과와 서비스 복귀 | 별도 지표로 구분 | 실제 RF 탐색만의 지연을 관측하는 구현 없음 |
| 클라우드와 실물 | Linux 코드 시험과 단말 시험을 구분 | Windows·S26+ 현장 실행은 수행하지 않음 |

특히 AOSP main 소스는 S26+ Android 16 또는 17의 삼성 소스와 동일한 코드라는 증거가 아니다. 보고서의 “AOSP에서 확인”이라는 한정어를 생략해서는 안 된다. API가 존재한다는 확인과 실제 삼성 단말에서 동작한다는 확인 사이의 공백이 남는다.

## 3. 잘못된 논리로 바뀌기 쉬운 표현

- “S26+는 최신이므로 우회하기 쉽다”는 주장은 채택하지 않았다. 최신 AP 성능과 권한 부여는 다른 문제다.
- “숨겨진 API를 호출하면 칩에 주입된다”는 주장은 채택하지 않았다. 확인한 시스템 API는 마지막 위치 캐시를 갱신한다.
- “네트워크 스캔 API가 있으므로 GPS로 등록이 빨라진다”는 주장은 채택하지 않았다. 위치별 후보 정보와 결과 반영 경로가 별도로 필요하다.
- “실물 시험이 없으므로 효과가 없다”는 주장은 채택하지 않았다. 올바른 표현은 효과 미측정이다.
- “root나 Shizuku가 있으면 반드시 된다”와 “둘 다 무조건 불가능하다”는 주장 모두 배제했다.

본문에 서로 양립할 수 없는 확정 사실을 동시에 주장한 중대한 내부 모순은 이번 검토에서 발견하지 못했다. 이는 내용이 모두 실기기로 검증됐다는 뜻이 아니다. 위 1절의 조건 미충족은 해결되지 않았으며 사용자에게 그대로 전달한다.

## 4. 구현과 산출물 검토

진단 도구는 기기를 지정한 ADB 읽기 명령을 실행한다. manifest의 요청 권한을 부여 권한으로 오인하지 않고, 기록의 누락·충돌은 null로 남긴다. 하지만 이 도구는 Samsung 전용 API나 실제 주입 함수를 실행하지 않으므로 S26+ 기능 호환성을 인증하는 도구가 아니다. 사용자 모델 확인도 출력값을 검토해야 한다.

합성 입력 5개 시험이 Python 3.12.14와 3.11.17에서 각각 통과했다. 같은 시험을 두 버전에서 돌린 것이며 10개의 독립 실물 실험이 아니다. 실행 계획 출력은 연결된 휴대폰에서 명령이 실행되었다는 의미가 아니다. 실물 시행 수는 0이다.

PDF는 실제 10쪽을 확인했고, 모든 쪽의 제목·쪽 번호를 텍스트 추출로 확인했다. 브라우저 레이아웃 검사상 본문 높이 초과가 없었고, 첫·마지막 쪽 미리보기를 시각 점검했다. 모든 페이지를 실물 인쇄해 검토한 것은 아니다.

검토 중 근거 발췌 파일에 판단과 무관한 전화 API 코드가 많이 포함된 것을 발견해, 이미 저장한 원본의 관련 지점만 남겼다. 이는 자료 정리이며 새로운 조사나 보고서 결론 변경이 아니다. 동결한 보고서 본문과 PDF는 검토 후 수정하지 않았다.

## 5. 최종 전달 사항

요청한 “S26+에 구현하여 기지국 탐색 개선이 있는지 확인”은 실기기 연결과 완결된 제어 경로가 없어 달성하지 못했다. 완료된 범위는 공개 자료 조사, 10쪽 보고서, 읽기 전용 사전 진단 도구 및 코드 시험이다. 기존 Fold3 앱을 기지국 가속 앱으로 바꾸어 표시하지 않았고, 기존 파일도 삭제하지 않았다.

다음 실행에 필요한 것은 GPS 추가 구매가 아니라 정확한 S26+ 모델·빌드의 진단 결과와, 그 결과에 맞는 API 실행 권한의 실기기 확인이다. 재개 명령은 README와 보고서 8쪽에 있다. 이 검토서를 전달하는 시점에는 추가 조사를 진행하지 않는다.
