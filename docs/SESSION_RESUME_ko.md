# 무료 플랜에서 작업을 이어가는 기준

**현재 재개 단계: ver.3(포트 통신), 기본 AT 응답 확인 완료.** [포트 통신 인수인계](../versions/v3/PORT_COMMUNICATION_RESUME_ko.md)를 우선 읽는다. Git 브랜치는 development/v3다. 사용자 Windows PC의 COM3에서 AT 3바이트 전송, OK 응답, 정상 close를 확인했다(사용자 제공 요약). [Windows 실행 절차](../versions/v3/AT_RESPONSE_CHECK_ko.md)는 보존하되 기본 AT 성공 시험은 반복하지 않는다. 후속 CLAC 목록 조회의 공식 근거 검토와 전용 도구 준비를 완료했다. [CLAC 실측](../versions/v3/CLAC_CHECK_ko.md)도 사용자 PC에서 OK·정상 close를 확인했다. 세 줄 미해석으로 목록 완전성은 미확인이다. 표준 CESQ 신호 품질 조회 도구 준비도 완료했다. CESQ 첫 실측은 OK·정상 close였으나 신호 값은 미해석 1줄로 확인하지 못했다. CESQ 진단 재조회도 CESQ 표기가 없는 미해석 한 줄이어서 반복을 중지했다. 다음은 [CSQ 절차](../versions/v3/CSQ_CHECK_ko.md)의 기본 신호 조회 계획 확인이며, 기본 AT/CLAC 시험은 반복하지 않는다. 위치 주입·셀 탐색 제어는 미검증이다. 아래 사전 점검 절차를 처음부터 반복하지 않는다.

최신 실기기 진행 상황은 [DEVICE_PREFLIGHT_ko.md](../versions/v3/DEVICE_PREFLIGHT_ko.md)를 우선 읽는다. 사용자 PC의 shell 권한 기록과 삼성 모뎀 포트 관찰까지 진행했다. 기본 AT의 OK 응답은 확인했으나 위치 주입·가속은 미검증이며, 이미 확인한 설정과 도움말 전체를 다시 수집하지 않는다.

V3 읽기 전용 제어 경로의 최신 재개 지점은 [CONTROL_PATHS_ko.md](../versions/v3/CONTROL_PATHS_ko.md)와 V3 CHANGELOG 첫 항목이다. 기존 S26 진단 도구를 재사용한 V3 점검은 합성 시험을 통과했다. 사용자 PC 권한 관찰은 위 최신 실기기 요약을 따르며, 실제 제어 호출·가속은 미검증이다. 사용자 PC에서 `python versions/v3/tools/control_probe.py --plan`부터 확인한다. 개인 결과는 `captures/v3/`에 보관한다.

사용자 확인(2026-11-10): 주된 중단 원인은 AI 사용량 한도 초과다. OAuth 재인증과 서비스 연결 만료는 부수적인 복구 항목이며 사용량 초과의 해결책이 아니다.

목표는 세션의 무기한 유지가 아니라, 세션 만료·클라우드 중단·모델 변경 이후에도 저장된 상태에서 개발을 이어가는 것이다. 무료 모델의 사용량 제한, OAuth 만료·철회, 무료 서비스의 제한은 코드로 제거할 수 없다.

## AI 작업 상태

새 대화는 AGENTS.md, project-state.json, versions/v3/CHANGELOG_ko.md를 먼저 읽는다. GitHub에서 development/v3를 가져오고 작업 트리와 V2 고정 해시를 확인한다. 기능 하나가 끝나거나 실행이 차단되면 변경·시험·실패 원인·미실행 항목·다음 명령을 CHANGELOG에 남기고 비밀정보 없이 커밋·푸시한다. 세션 종료 때 저장할 기회가 없을 수 있으므로 장시간 작업 끝까지 저장을 미루지 않는다.

진행 상태는 GitHub의 추적 파일이 기준이다. 채팅 기억이나 클라우드 작업 폴더의 영구 존속을 전제하지 않는다. 개인 원자료·서명키·.env는 GitHub에 포함하지 않는다. 개인 ZIP의 채팅 다운로드는 실패했고 사용자 PC로 전체 백업 이전은 아직 확인되지 않았다. 특히 서명키를 PC로 이전했다고 가정하지 않는다.

## 서비스 재연결

- GitHub: 저장소와 브랜치는 영구 식별자로 남기고, 연결 실패 시 인증 상태를 조회한다. 401/403이나 철회 시 사용자 OAuth 재연결이 필요할 수 있다. 토큰 값을 채팅·로그·저장소에 붙이지 않는다.
- Supabase: AI 도구의 OAuth와 앱 사용자의 Auth 세션은 별개다. 기존 앱은 src/proxy.ts에서 getUser()와 갱신 쿠키 전달을 사용한다. 이것은 웹 요청에 따른 갱신 경로이며 AI 연결의 영구 유지 기능이 아니다. 프로젝트 정지·네트워크 장애·갱신 토큰 철회는 따로 처리한다. 무료 서비스 제한으로 정지된 프로젝트는 대시보드에서 상태와 복구 방법을 확인한다.
- Vercel: 배포 URL·프로젝트 연결 정보를 추적하되 런타임 환경변수와 배포 인증은 해당 서비스의 보관소를 사용한다. 브라우저 로그인 종료와 배포 사이트 가동 여부를 구분한다. 무료 플랜의 할당량·실행 시간·프로젝트 상태는 별도 제한이다.
- 서비스 오류는 원인을 분류해 제한적으로 재시도한다. 같은 401/403에 무한 재시도하거나 인증 검증을 생략하지 않는다. 토큰 수명 무제한화, 자격 증명 코드 삽입, 무료 정지를 피하기 위한 무의미한 주기 호출은 하지 않는다.

## 재개 확인

```text
python tools/resume_check.py
```

이 명령은 로컬 브랜치·V2 기준점·작업 트리를 확인하고 서비스 인증을 ‘미검증’으로 표시한다. 환경 파일 존재만으로 인증 성공을 판정하지 않는다. 그다음 현재 제공되는 연결 도구로 GitHub/Supabase/Vercel을 각각 읽기 전용 조회한다. 인증이 만료됐다면 연결 설정에서 해당 서비스만 다시 인증한다. 이 체크 도구는 토큰을 읽거나 출력하지 않으며 네트워크 연결을 보장하지 않는다.

새 작업 환경에는 Python·Node·Android SDK 등 빌드 도구를 다시 설치해야 할 수 있다. 그 설치와 외부 인증 완료는 Git 커밋만으로 복원되지 않는다. APK에 필요한 개발 키는 원래 비공개 보관 위치 또는 사용자가 별도로 확보한 백업에서 가져와야 한다.

## AI 사용량 한도에 대한 실행 규칙

- 한도 자체를 없애거나 새 대화·계정·무의미한 요청으로 우회하지 않는다. 새 대화는 문맥을 줄일 수 있지만 계정 사용량을 초기화하지 않는다.
- 모델 변경은 사용자가 선택한다. AI가 자동으로 저비용 모델로 전환하거나 남은 사용량을 항상 읽을 수 있다고 가정하지 않는다.
- 작업을 작은 기능 하나로 나누고, 중간에도 재개 가능한 결과가 생기면 저장한다. 매 메시지마다 중복 커밋하거나 필요 없는 전체 빌드·전체 자료 재조사를 반복하지 않는다.
- 저장할 때 완료·변경 파일·검증·미실행·다음 명령을 CHANGELOG에 남긴다. 단위 작업의 커밋과 푸시를 확인한다. 한도 도달 경고를 받아도 추가 작업이 허용된다면 신규 기능보다 현재 상태 저장을 우선한다.
- 강제 중단 시 마지막 체크포인트 이후 미저장 변경은 손실될 수 있다. 중단 순간에 반드시 저장할 실행 기회가 주어진다고 보장하지 않는다.
- 사용량 초기화 후 같은 대화 또는 새 대화에서 재개한다. 다른 모델 사용이 허용되는지는 해당 계정의 사용량 화면에서 확인한다. 모델마다 한도가 완전히 독립적이라고 가정하지 않는다.
- 작업 상태를 GitHub에 저장해 두어도 한도를 소진한 AI가 계속 개발하는 것은 아니다. 무료 지속 실행·무제한 사용량을 구현했다고 표시하지 않는다.
