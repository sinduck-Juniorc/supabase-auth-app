# 실기기 사전 확인 요약 · 2026-11-10

출처는 사용자가 PC에서 실행해 전달한 출력과 설정 설명이다. 클라우드에서 단말을 직접 조회하거나 결과를 독립 재현한 것은 아니다. 개인 원문·시리얼·사용자 폴더 경로·설정 JSONL은 저장소에 포함하지 않는다.

## 확인된 관찰

| 항목 | 사용자 제공 결과 |
|---|---|
| 모델 / Android / SDK / One UI 속성 | SM-S947N / 17 / 37 / 90000 |
| ADB 상태 | 재부팅 후 `device` |
| shell UID | 2000 |
| shell 패키지 권한 기록 | NETWORK_SCAN, MODIFY_PHONE_STATE, LOCATION_HARDWARE, ACCESS_FINE_LOCATION 모두 granted=true |
| shell 패키지 통신사 권한 조회 | `cmd phone has-carrier-privileges com.android.shell` → false |
| V3 설치 경로 조회 | `pm path org.zetamesh.gnss.v3` 출력 없음. V3 설치 확인 안 됨 |
| 위치 서비스 도움말 | 테스트 제공자·extra command가 보임. 직접 실제 위치를 입력하는 명령은 도움말에서 확인 안 됨 |
| 전화 서비스 도움말 | 통신사 권한 조회·설정/시험 명령 등이 보임. 최근 위치 입력으로 셀 탐색을 개선하는 직접 명령은 확인 안 됨 |
| 3GPP AT 명령 설정 | 사용자가 켰고 재부팅 완료했다고 보고 |
| Windows 모뎀 | SAMSUNG Mobile USB Modem, 상태 OK, 사용자 확인 포트 COM3, 서비스 modem |
| USB 구성 속성 | `sys.usb.config` → mtp,adb |

AT 설정 변경 전후의 포트 목록을 같은 조건으로 대조하지 않았다. 따라서 설정을 켜서 COM3가 새로 생겼다고 단정하지 않는다. `modem`은 Windows 서비스 이름이며 AT 응답·모뎀 제어 권한을 증명하지 않는다. `mtp,adb`만으로 제조사 모뎀 인터페이스의 접근 가능·불가능을 판정하지 않는다.

## 개발자 옵션 검토

사용자가 제공한 목록에서 AI GRO는 켜짐으로 보고됐고 설명은 파일 다운로드용 네트워크 매개변수 최적화다. 업링크 지연 최적화도 켜짐으로 보고됐다. 최근 위치를 모뎀에 전달하는 경로라는 증거는 없다. 가상 모뎀은 시험용, 가상 위치 앱은 mock 경로, 강제 GNSS 측정은 측정 옵션으로 구분한다. 이들을 실제 기지국 탐색 제어 또는 권한 부여 기능으로 간주하지 않는다.

## 판정과 다음 작업

읽기 전용 사전 확인으로 shell의 관련 권한 기록과 Windows 모뎀 포트의 존재를 확인했다. 통신사 권한 false는 별도의 MODIFY_PHONE_STATE 부여 기록을 무효화하지 않는다. 패키지 덤프의 granted 기록도 사용자·AppOps·서비스별 최종 허용 판정이나 앱으로의 권한 이전을 증명하지 않는다.

AT 명령은 보내지 않았고 COM3 열기·응답 수신도 시험하지 않았다. V3 설치·Binder 실행·GNSS HAL 주입·실제 셀 검색/등록·성능 비교는 미실행이다. 완전 불가능 판정과 성공 판정 모두 보류한다.

다음 작업은 COM3의 AT 지원 근거·연결 조건을 확인하고 읽기 질의의 범위를 설계하는 것이다. 출처 없이 삼성 전용 명령을 추측하거나 포트의 모든 명령을 탐색하지 않는다. PC에서 포트를 열면 초기화나 DTR/RTS 동작이 발생할 수 있으므로 단순 열기도 읽기 전용이라고 단정하지 않는다. 설정 변경·모뎀 재시작·AT 쓰기 명령은 현재 사전 점검에 포함하지 않는다.

재개 시 반복 실행할 필요가 있는 명령은 연결 확인 한 줄뿐이다. 경로는 사용자의 기존 CMD 위치 기준이며 AT 전송은 하지 않는다.

```cmd
platform-tools\adb.exe devices
```

개인 전체 ZIP의 PC 다운로드와 서명키 이전은 여전히 미확인이다. 원문 백업을 완료했다고 가정하지 않는다.

## 2026-11-10 · 이전 옵션 자료 재검토

사용자 지적으로 이전 「삼성 개발자 옵션 스크린샷 정리」 대화의 JSONL 생성 기록과 전사 내용을 다시 조회했다. 이미지 16장/중복 제외 화면 15장/126개 기록 및 별도 AI GRO JSONL 생성 기록을 확인했다. 현재 클라우드에 원본 JSONL 파일이 있는 것은 아니며 대화의 생성 기록/전사와 저장소 요약을 대조한 것이다. 원문·개인 PC 경로는 공개하지 않는다.

| 항목 | 촬영 당시 기록 | 현재 판단 |
| --- | --- | --- |
| 3GPP AT 명령 | off, 켜거나 끄는 옵션 | 이후 사용자 on·재부팅 보고가 더 최신. 옛 off를 현재 원인으로 단정하지 않음 |
| USB 디버깅 | on | ADB 경로이며 CSQ 허용 여부와 별개 |
| 기본 USB 구성 | 하위 메뉴, 이 행에 선택값 없음 | 최신 사용자 관찰 mtp,adb를 따름 |
| 가상 모뎀 허용 | off, 계측 시험용 | 실물 모뎀 오류 해결을 위해 켤 근거 없음 |
| 가상 위치 앱 | 설정되어 있지 않음 | mock 경로이며 실물 모뎀 위치 주입 성공 근거 아님 |
| 강제 GNSS 측정 | off | 측정 옵션이며 CSQ 권한 부여 기능으로 확인되지 않음 |
| 업링크 지연 시간 최적화 | on | 일부 모바일 데이터 서비스 지연 개선 설명. CSQ 허용 근거 아님 |
| AI GRO | 별도 촬영 on | 다운로드 네트워크 최적화 설명. AT 허용/위치 주입 근거 아님 |

원자료는 촬영 시점의 상태다. 현재 3GPP AT 상태가 필요하면 화면 상태를 읽기만 하고 자동 토글/재부팅하지 않는다. 원본 126행 JSONL 파일 전체를 새로 열어 검증했다고 표현하지 않는다.
