# 에코 트레킹 기획 및 구조 변경 판단

## 목표

등산 중 스마트폰이 경로를 기록하고 필요한 데이터를 전달하면서, 기존 트래킹 앱과 비슷한 기록·전송 품질에서 배터리를 덜 쓰도록 한다. ‘에코’는 저전력 트래킹을 뜻한다. 앱에서 A-GPS 보조정보 요청과 A-BLE를 통한 외부 위치 주입은 제품 범위에서 제외한다. Bluetooth 메시와 Wi‑Fi는 앱 데이터 전달에 사용한다.

## 기존 구조와 비교

| 기존 자료와 구현 | 판정 |
|---|---|
| [GNSS 보조 보고서](../../android/gnss-assist/REPORT_ko.md)와 `MainActivity`는 GNSS 첫 위치 획득 시간(TTFF)을 비교하고 시간·PSDS 보조 요청을 호출한다. | **제품의 메인 구조를 변경한다.** 보조 요청과 TTFF 실험 모드는 제품 실행 경로에서 제외한다. 일반 Android 위치 API로 트래킹 세션을 운용하고, 위치 요청·저장·전송 정책을 앱이 관리한다. |
| [실내 관찰 검증](../../android/gnss-assist/WALK_VALIDATION_20261110_ko.md)과 현재 런처 `WalkActivity`는 1초 간격 GPS를 요청하고 화면이 숨겨지면 관찰을 종료한다. | 이벤트 시간·순서 검증과 구독 해제 패턴은 재사용 후보다. 화면 잠금이 포함되는 등산에서는 세션 수명주기, 위치 요청 정책, 로컬 경로 저장을 새로 설계해야 한다. |
| [50노드 연구](../../research/ZetaMesh50/README.md)와 [UNO R4 WiFi 검증](../../firmware/uno-r4-wifi/README.md)은 자체 BLE 광고 중계 시뮬레이션과 가상 위치 패킷 진단을 다룬다. | 전달률·지연·에너지 시험 방법은 참고할 수 있다. 표준 Bluetooth Mesh, BLE↔Wi‑Fi 게이트웨이, Android 폰의 배터리 절감은 별도로 구현·검증해야 한다. 기존 모듈을 필수 구성으로 채택할 근거는 아직 없다. |
| [V3 포트 통신 기록](PORT_COMMUNICATION_RESUME_ko.md)은 기본 모뎀 응답과 신호 조회 결과를 담는다. | 기존 실험 이력으로 보존한다. 새 제품 검증은 앱의 등산 세션과 소비량 비교를 기준으로 진행한다. 추가 AT 명령 전송은 중지한다. |

## 앱 구조 초안

1. 사용자가 시작한 트래킹 세션은 화면을 잠근 동안에도 경로를 기록할 수 있도록 설계한다. 위치 정확도·요청 주기·묶음 전달을 조절하고, 경로 공백과 오차가 허용 범위에 드는지 실측한다. [Android 위치와 배터리 안내](https://developer.android.com/develop/sensors-and-location/location/battery)
2. 경로는 단말에 먼저 저장한다. 전송 요구가 있을 때는 대기열을 사용해 중계 기기와 가까울 때 필요한 데이터만 Bluetooth 메시로 전달하거나 Wi‑Fi가 연결될 때 묶어서 동기화하는 방안을 시험한다. 연결이 끊기면 로컬 기록을 이어가고, 재연결 시 중복 전송 여부를 확인한다. Wi‑Fi LAN·인터넷 또는 Wi‑Fi Direct의 역할은 실제 연결 구성을 확인한 뒤 정한다. [Android BLE 백그라운드 안내](https://developer.android.com/develop/connectivity/bluetooth/ble/background) · [Wi‑Fi Direct 안내](https://developer.android.com/develop/connectivity/wifi/wifip2p)
3. 메시 탐색·광고·재시도까지 포함해 배터리를 측정한다. 메시 경유 전송의 총비용과 Wi‑Fi 연결을 기다렸다가 직접 전송하는 총비용을 비교해 전송 정책을 결정한다.

## 배터리 비교 계획

- **제품 비교**는 기존 트래킹 앱과 에코 트레킹을 동일 스마트폰·코스·활동 시간에서 번갈아 실행한다. 화면 켜짐 시간·밝기, 지도 표시와 동기화 조건, 배터리 시작 잔량, OS 절전 설정, 온도와 망 상태를 통제하거나 기록한다. 같은 단말에서 두 앱을 동시에 실행하면 비교가 섞일 수 있으므로 별도 주행으로 반복한다.
- **원인 분리**는 에코 트레킹에서 위치 기록 설정을 고정하고 ① 로컬 기록만, ② 동일 데이터 Wi‑Fi 전송, ③ Bluetooth 메시와 Wi‑Fi 연계 전송을 비교한다. ①은 기록 자체의 소비량을 파악하는 조건이다. ②·③은 동일 전송량과 전달 요구를 두고 연결 탐색·재시도까지 포함해 비교한다.
- **측정과 판정**은 가능할 경우 단말 전체의 배터리 전하 감소량을 mAh 또는 mAh/h로 비교하고, 배터리 %p/h는 참고값으로 기록한다. 측정 기간과 반복 횟수를 명시하고 중앙값과 편차를 함께 보고한다. 경로 오차·누락, 전달 성공률·지연도 함께 기록한다. 경로 품질이나 전달 조건이 다른 경우 소비량 차이만으로 개선 판정을 내리지 않는다. 휴대용 중계 장비를 쓰면 그 장비의 소비량도 별도로 기록한다. [Android Power Profiler 안내](https://developer.android.com/studio/profile/power-profiler)

## 현재 판단할 수 없는 항목

- S26+에서 화면 잠금 상태의 위치 기록과 메시 중계가 얼마나 안정적으로 동작하는지, BLE와 Wi‑Fi의 탐색·재연결 비용이 얼마인지 모른다.
- 비교할 기존 앱과 기능 설정, 목표 배터리 절감률, 경로 오차·누락 허용치, 메시 전송 데이터와 허용 지연은 아직 정해지지 않았다.
- 표준 Bluetooth Mesh 채택 여부, 폰과 중계기 역할, Wi‑Fi 접속 구조, 등산로의 중계기 밀도는 아직 정해지지 않았다.
- S26+에서 확보할 수 있는 배터리 계측 항목과 정밀도, 기존 앱 대비 절감량은 확인되지 않았다. 이전 실내 관찰·TTFF·가상 노드 실험에는 이 비교에 필요한 배터리 실측값이 없다.

다음 작업은 비교할 기존 앱의 기록·동기화 설정과 단말에서 읽을 수 있는 배터리 지표를 확인하고, 화면 잠금이 포함된 동일 코스 비교 조건을 정하는 것이다.

실행 자료는 [BLE 0·1 시연](ECO_TREKKING_DEMO_ko.md)과 [배터리·1홉 계측](ECO_TREKKING_PROBE_ko.md)에 있다.
