# 첫 이동 관찰 로그 검증과 0.2.1 수정

검토일: 2026-11-10 한국 시간. 사용자 제공 0.2.0 로그의 유효성을 먼저 확인한 뒤 수정했다. 사용자 원자료와 세션 식별자는 공개 저장소에 올리지 않았다.

## 유효성 결과

9개 JSON 이벤트, 1개 세션이며 시작·실외 위치 준비·실내 도착·종료 순서가 정상이다. 단조 시각 역전이 없고 벽시계 증가량과도 일치한다. 종료 시 GPS와 전화 상태 구독 해제 성공을 기록했다. 이는 해제 API가 예외 없이 반환했다는 앱 기록으로, 하드웨어 전력 소비가 0임을 증명하는 값은 아니다.

| 항목 | 값 |
|---|---:|
| 전체 관찰 | 160.054초 |
| 시작 → 실외 위치 준비 | 40.073초 |
| 시작 → 실내 도착 버튼 | 80.427초 |
| 실내 도착 → 종료 | 79.627초 |
| 실내 도착 당시 실외 위치의 나이 | 40.387초 |
| Android 추정 정확도 | 13.265306m |
| 통신 상태 스냅샷 | 1개, 시작 직후 |
| 실내 통신 스냅샷 | 0개 |

실외 위치 준비 시간은 관찰 시작부터 위치 콜백까지의 시간이며 엔진 TTFF와 동일하지 않다. 실내 도착은 사용자가 누른 표식이며 실내임을 센서로 증명한 것이 아니다. 위치 정확도 추정치가 약 13.3m이고 로그에 좌표도 없으므로 약 10m 이동을 이 기록으로 검증할 수 없다.

시작 직후에는 서비스 이용 가능(state 0), 데이터 연결(state 2), LTE(network_type 13), 기본 경로 셀룰러, OS 인터넷 검증 상태가 관측됐다. 이후 상태 변화 이벤트가 없지만 실내 표본도 없어 연속 연결을 입증하지 못한다. LTE 표기는 5G NSA 표시와 다를 수 있다. 보조 개입은 none이다. 기지국 재탐색·등록 복구·위치 주입·가속 효과는 평가하지 않았다.

## 코드에서 발견한 문제

1. 기존 앱은 네트워크 문자열이 변할 때만 기록했다. 실내 도착 시점과 이후에도 조회가 지속됐는지 확인하기 어려웠다.
2. outdoor_location_ready와 observation_end에 넣은 구간 경과 시간의 elapsed_ms 키를 공통 로거가 부팅 후 단조 시각으로 덮어썼다. 이번 값은 시작 이벤트와의 차이로 복원했다. 원자료는 수정하지 않았다.

## 0.2.1 변경

- 네트워크 정보가 변하지 않아도 약 15초 간격으로 기록한다. 2초 주기의 조회 루프에서 실행되므로 실제 간격은 보통 약 16초이며 지연될 수 있다.
- 실내 도착 버튼과 관찰 종료 시점에 네트워크 스냅샷을 강제로 조회·기록한다. 조회 오류도 기록한다.
- 스냅샷에 실외/실내 단계, 기록 사유, 최근 실외 위치의 나이, 마지막 서비스·데이터 상태와 각 콜백의 경과 시간을 추가한다. 전화 상태는 마지막 콜백 값이며 스냅샷 시점에 새 RF 측정을 했다는 뜻이 아니다.
- 구간 경과 시간은 session_duration_ms, 이벤트 단조 시각은 elapsed_ms로 분리한다. schema_version 2와 순번을 기록해 누락·중복을 검토할 수 있게 한다.
- tools/validate_walk.py로 기존·새 로그의 순서, 시각, 시작/종료, 실내 표본, 순번을 검사한다. 가속 여부는 자동으로 참이라고 판정하지 않는다.

## 검증

Java 위치 유효성·자원 정리 검사, Python 8개 검사, SDK 35 빌드와 APK 서명 검사가 통과했다. 로그 검증기는 실제 업로드에 ‘구조 유효 / 실내 통신 표본 없음’을 반환했다. 새 APK는 0.2.1, versionCode 4다. S26+에서 수정된 주기 기록과 UI는 아직 미실행이다.

```text
python tools/validate_walk.py 실제로그.jsonl --out 검증결과.json
python -m unittest discover -s tests -p "test_*.py" -v
```

## 다음 실행

같은 방식으로 실외 위치 준비 → 실내 도착 → 같은 지점에서 60~90초 관찰 → 종료 → 파일 저장을 한 번 진행한다. 현재 연결이 정상이라면 연결 복구 시간은 평가할 수 없다. 기지국 탐색 개선을 검증하려면 실제 제어 경로와 적절한 대조 조건이 별도로 필요하다. 이번 수정은 관찰의 빈틈을 보완하며 통신 설정·모뎀·좌표 주입을 변경하지 않는다.
