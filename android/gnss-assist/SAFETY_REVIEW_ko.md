# 측정 전 GNSS 진단 APK 안전성 코드 검토

검토일: 2026-11-09. 대상: ZetaMesh GNSS 진단 0.1.0, `org.zetamesh.gnss`. 사용자 단말 정보: 한국형 Galaxy S26+, One UI 9.0 / Android 17. 실제 단말에는 접근하지 않았다. 검토 기준 코드는 커밋 `eabb3df8dcc99d83307871f79c91165235c10bda`이며 앱 실행 코드는 기존 Fold3용 버전이다.

## 결론

펌웨어·부트로더 쓰기, root·셸 실행, 모뎀 설정 변경, 사용자 파일 자동 삭제, 전압·클럭·열 보호 제어 등 직접 손상으로 이어질 수 있는 동작을 검토한 앱 코드와 APK에서 발견하지 못했다. 그러나 종료 처리와 자원 사용 제한에 아래 결함·한계가 있으므로 **현재 버전은 해당 부분을 보강한 뒤 측정하는 것을 권고한다.**

이는 물리적 안전 인증이나 Android 17 삼성 드라이버의 무결함 보증이 아니다. 검토는 소스·매니페스트·배포 APK·독립 디렉터리 재빌드의 대조이며 실물 전력·발열·수명 시험은 수행하지 않았다. 요청에 따라 리뷰 결과를 남겼으며 앱 소스와 배포 APK는 변경하지 않았다.

## 발견 사항

### 1. 중간 우선순위 — 종료 중 예외가 나면 나머지 위치 구독 해제를 건너뜀

위치: [MainActivity.java 142행](src/org/zetamesh/gnss/MainActivity.java#L142), 특히 144~145행.

`stopTrial()`은 먼저 `trial.active=false`로 바꾸고 타이머를 취소한 뒤, GPS 리스너·네트워크 리스너·GNSS 콜백 해제를 하나의 try 블록에서 순서대로 실행한다. 앞의 해제 호출이 예외를 던지면 뒤의 해제는 시도되지 않는다. 이후 onStop이나 중단 버튼이 호출되어도 active=false이므로 즉시 반환하고 정리를 다시 시도하지 않는다.

삼성 위치 서비스나 권한·서비스 상태 변화로 해제 호출이 실패한 경우, 일부 구독이 등록된 상태로 남을 가능성이 있다. 콜백의 active 검사는 앱의 후속 처리를 막지만 위치 서비스의 등록 자체를 해제하지는 않는다. 불필요한 위치 수신과 배터리 소모로 이어질 수 있으며, 하드웨어 손상이 실제 발생했다는 증거는 아니다.

권고: 각 해제를 독립적으로 시도하고, 시험 종료 상태와 자원 등록 상태를 분리한다. 부분 실패 후 재정리할 수 있게 하며 한 작업의 예외로 다른 작업이 생략되지 않도록 검증한다.

### 2. 중간 우선순위 — 120초는 강제 상한이 아닌 UI 스레드의 예약 시간

위치: [MainActivity.java 116행](src/org/zetamesh/gnss/MainActivity.java#L116), 66~70행 및 123행.

종료 타이머와 위치 콜백은 메인 Looper를 사용하고, 로그 파일 쓰기와 시스템 추가 명령도 UI 스레드에서 수행한다. 파일 I/O 또는 Binder 호출이 오래 지연되면 타이머도 그동안 실행되지 못한다. 따라서 앞서 안내한 “최대 120초”는 정상 처리 상태의 예정 시간이며, 어떤 오류 상황에서도 120초 안에 수신이 반드시 끝난다는 뜻으로 사용하면 안 된다.

권고: 기록·잠재적 지연 작업을 UI 스레드와 분리하고, 앱 복귀·콜백 시 단조 시각 기반 마감 검사를 추가한다. 드라이버·서비스가 응답하지 않는 상황까지 일반 앱이 절대적인 시간 상한을 보장할 수 있다고 설명하지 않는다.

### 3. 낮은 우선순위 — 로그 파일 크기 제한이 없음

위치: [MainActivity.java 69행](src/org/zetamesh/gnss/MainActivity.java#L69), 158행.

모든 실행이 같은 앱 내부 JSONL 파일에 계속 추가되며 회전·크기 상한·보존 기간이 없다. 장기간 반복하면 앱 저장공간 사용량이 증가한다. 큰 파일의 내보내기도 UI 스레드에서 처리돼 화면이 멈출 수 있다. 몇 번의 짧은 시험으로 저장소가 가득 찬다고 주장하는 것은 아니며, 반복 사용 시의 방어가 없는 문제다.

권고: 파일 크기·보존 개수 제한과 사용자 주도의 정리 기능을 추가하고 내보내기는 작업 스레드에서 수행한다. 파일 회전 시 기존 실험 로그를 알림 없이 잃지 않도록 설계한다.

## 파괴적 동작·통신·권한 점검

| 항목 | 확인 결과 |
|---|---|
| root, su, Runtime.exec, 셸·ADB 실행 | 앱 코드에 없음 |
| 펌웨어·부트로더·기저대역 쓰기 | 해당 코드·패키지 내용 없음 |
| SIM·기지국·비행기 모드 변경 | 해당 API 호출과 권한 없음 |
| GNSS 보조정보 삭제 | delete_aiding_data 호출 없음 |
| 보조정보 갱신 | B/C가 force_time_injection·force_psds_injection을 시스템에 요청 |
| 임의 좌표·시각 주입 | 앱이 입력값을 지정하는 주입 구현 없음 |
| 영구 위치 설정 변경 | 설정 화면을 열 뿐, 앱이 위치 설정 값을 직접 쓰지 않음 |
| 백그라운드 서비스·부팅 실행 | 서비스·수신기 선언 없음, onStop에서 종료 시도 |
| 네이티브 코드·외부 실행 파일 | APK에 .so나 별도 실행 파일 없음 |
| 사용자 파일 접근 | 내부 로그 기록, 사용자가 선택한 문서로 내보내기 |
| 자동 로그 전송 | 직접 네트워크 요청 구현·INTERNET 권한 없음 |

실제 권한은 ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, ACCESS_LOCATION_EXTRA_COMMANDS, ACCESS_NETWORK_STATE 네 개다. 매니페스트는 위치 하드웨어 사용을 선언한다. 위치 수신과 화면 유지 자체는 전력을 소모하며 일시적 발열이 발생할 수 있다. 앱은 배터리 온도를 감시하거나 온도에 따라 중단하는 코드를 갖추지 않았다.

B/C는 단순한 읽기 전용 시험이 아니다. 시스템에 보조정보 갱신을 요청하므로 OS의 GNSS 보조 상태가 바뀌거나 시스템 측 다운로드가 발생할 수 있다. 앱에 INTERNET 권한이 없다는 사실을 “통신이 전혀 발생하지 않는다”로 해석하면 안 된다. 앱의 측정 중단이 이미 시스템에 보낸 갱신 작업을 취소한다는 보장도 없다. C의 네트워크 위치 제공자도 OS 설정에 따라 시스템의 통신을 사용할 수 있다. 이러한 시스템 내부 동작은 이번 APK 정적 검토만으로 전부 확인할 수 없다.

내보내기는 Android 문서 선택기를 사용한다. 사용자가 클라우드 문서 제공자를 선택하면 그 제공자에 파일이 저장될 수 있다. 앱의 자동 업로드가 없다는 설명과 사용자가 직접 선택한 클라우드 저장은 구분한다. 로그에는 좌표가 없지만 모델·빌드 fingerprint·시간·측정 상태가 포함된다.

## 배포 APK와 소스의 대응 검증

검토한 APK SHA-256:

```text
54e70a699971624f6cfe7d833b61dc64f0eae38dbe46a66d16a8d580d4be40a5
```

- 이전에 제공한 GitHub 다운로드 URL에서 받은 APK와 로컬 배포 APK가 바이트 단위로 일치했다.
- apksigner 검사에서 v3 서명이 유효했다. 개발 서명이며 제조사 안전 인증을 뜻하지 않는다.
- 소스 파일 해시가 기존 빌드 기록과 일치했다.
- 별도 디렉터리에서 재빌드했고 기존 Java 상태 검사가 통과했다.
- 재빌드 APK의 classes.dex, AndroidManifest.xml, resources.arsc가 배포 APK의 대응 파일과 모두 바이트 단위로 일치했다.
- APK 전체 해시는 재빌드본과 다르다. 전체 APK의 비트 단위 재현을 주장하지 않으며, 실행 코드·매니페스트·리소스의 일치만 확인했다.

## 측정 전 판단

직접적인 영구 손상 동작은 발견하지 못했지만 자원 해제의 실패 경로가 남아 있다. 첫 시험을 바로 진행하라고 권고하기보다 종료 처리·시간 제한 설명·로그 제한을 보강하는 것이 적절하다. 이미 실행했다면 측정을 중단하고 앱 정보에서 강제 종료할 수 있다. 다만 강제 종료도 시스템이 별도로 진행하는 보조정보 갱신의 취소를 보장하지 않는다.

S26+ Android 17에서의 드라이버 안정성, 실제 발열·배터리 소모, 콜백 해제 성공 여부는 미검증이다. 외부 자료 재조사 없이 현재 코드, 기존에 저장한 AOSP 근거, 실제 배포 파일을 검토했다.
